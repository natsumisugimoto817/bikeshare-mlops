# Bike Sharing Demand Forecasting

Data preparation, leakage-safe feature engineering, a time-based train/validation/test split, and a simple baseline forecast for the **UCI Bike Sharing Dataset** (daily Capital Bikeshare records, 2011–2012).

The current implementation is documented in [`src/01_Preprocess.ipynb`](src/01_Preprocess.ipynb). An illustrated, self-contained English-language summary is available in [`bikeshare_report_EN.html`](bikeshare_report_EN.html).

## Project objective

Forecast **total bike rentals on day N (`cnt`)** on the **evening of day N−1** to support next-day staffing and fleet planning.

**Feature availability assumption:** Observed weather and rental totals are not available until the following morning. When forecasting day N, the latest available observed values are therefore from **day N−2**. Calendar variables for day N are known in advance.

## What the notebook does

### 1. Data inspection

- Reads `../data/raw/day.csv`.
- Checks column types, missing values, and exact duplicate rows.
- Converts `dteday` to datetime and sorts by date.
- Confirms the recorded date range. **An explicit missing-calendar-day check is not present** in the notebook.

### 2. Feature availability and leakage prevention

Calendar features for the target day: `season`, `yr`, `mnth`, `holiday`, `weekday`, `workingday`.

Historical features delayed by two days: `weathersit_lag2`, `temp_lag2`, `atemp_lag2`, `hum_lag2`, `windspeed_lag2`, `casual_lag2`, `registered_lag2`, `cnt_lag2`.

The target is `cnt`. The record ID `instant` is excluded; `dteday` is used to derive features and split chronologically, but not as a direct model input. **Target-day observations and day N−1 observations must not be used as predictors** under the stated forecasting assumptions.

### 3. Lag features and chronological split

The notebook creates eight features with `shift(2)` **before splitting the data**, then removes the first two rows where lag values are unavailable.

| Split | Dates | Rows |
| --- | --- | ---: |
| Train | 2011-01-03 to 2012-04-30 | 484 |
| Validation | 2012-05-01 to 2012-08-31 | 123 |
| Test | 2012-09-01 to 2012-12-31 | 122 |

After splitting, the `dteday` column is dropped from the exported files. The notebook writes `../data/processed/train.csv`, `valid.csv`, and `test.csv`.

### 4. Baseline and evaluation

The **naive baseline** forecasts the number of rentals on day N using the actual count from day N−2:

```python
valid["diff_abs"] = (valid["cnt"] - valid["cnt_lag2"]).abs()
MAE_base = valid["diff_abs"].mean()
RMSE_base = np.sqrt((valid["diff_abs"] ** 2).mean())
```

- **MAE:** Average absolute prediction error, measured in rentals.
- **RMSE:** Root mean squared error, also in rentals; penalizes larger misses more heavily.

The reported scores are **MAE = 1,011.20** and **RMSE = 1,336.42** on the validation period.

### 5. MLflow experiment tracking

The notebook currently logs:

| MLflow field | Value |
| --- | --- |
| Experiment | `Bike_Sharing` |
| Run name | `Baseline_Lag2` |
| Parameter | `lag_days = 2` |

The notebook's tracking URI is **hard-coded to the original Windows machine**:

```python
mlflow.set_tracking_uri("sqlite:///d:/03_Python/bikeshare-mlops/src/mlflow.db")
```

**Change this URI before running on another computer.** If your Python working directory is `src/`, the following is a simpler local alternative:

```python
mlflow.set_tracking_uri("sqlite:///mlflow.db")
```

To inspect that database in the MLflow browser UI, open a **new terminal at the repository root** and start:

```powershell
mlflow ui --backend-store-uri "sqlite:///src/mlflow.db" --port 5000
```

Then open [http://127.0.0.1:5000](http://127.0.0.1:5000), select the `Bike_Sharing` experiment, and open the `Baseline_Lag2` run. If you use a different database path, use that same path for both logging and the UI.

**Important:** A local SQLite database is **not a shared team Tracking Server**. The current notebook does not configure a remote server, log prediction CSVs as artifacts, or register a model version. Those steps can be added later if the team needs them.
