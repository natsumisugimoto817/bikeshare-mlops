02
THE FORECAST RULE

What are we predicting, and when?

The target is total rentals on day N. The forecast is generated on the evening of day N−1.

N − 2
✅ Latest available observations

The most recent known rental counts and observed weather.

N − 1
💡 Forecast issued in the evening

The same-day rental totals and weather observations are not yet available.

N
🎯 Target: next-day rentals

Predict the observed total cnt for this day.

6 FEATURES

📆 Known calendar features

Use values for the target date (day N).

seasonyrmnthholidayweekdayworkingday
8 FEATURES

⏪ Historical observations

Use shift(2) to access day N−2 or earlier.

weathersit_lag2temp_lag2atemp_lag2hum_lag2windspeed_lag2casual_lag2registered_lag2cnt_lag2
🔒Leakage prevention:Do not use target-day cnt, observed weather or rider counts as inputs. dteday is used for chronological splitting and feature engineering, not as a direct input. instant is excluded because it is a record identifier.
03
FEATURE ENGINEERING

Build the two-day lag features.

For eight delayed observation fields, create lag2 features. The baseline forecast uses cnt_lag2 .

cnt_lag2 = cnt.shift(2)Prediction = actual rentals two days before the target date

🧹 Drop the first two days

shift(2) leaves no historical values for the first two days.

8 lagged fields × 2 days = 16 missing cells. These are introduced by lag engineering, not missing values in the original data.

features_n2 = [
    'weathersit', 'temp', 'atemp', 'hum',
    'windspeed', 'casual', 'registered', 'cnt'
]
for feature in features_n2:
    df[f'{feature}_lag2'] = df[feature].shift(2)

df_clean = df.dropna().copy()
